# Sources

This skill is a synthesis written for this project. No code or prose was copied from the repos
below; ideas were read, reconciled and rewritten. All 12 were read on 2026-10-27 (README plus
their SKILL.md, rules and DESIGN.md files). Nothing was installed or run from them.

## Conflicts between sources and how they were settled

| Topic                        | Disagreement                                                                                                          | Decision here                                                                      | Why                                                                             |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| White cards on a tinted page | Hallmark bans it; Taste allows bordered panels on app screens                                                         | Allowed: `bg-white` panels with a `stone-200` border on `stone-50`                 | This is an app screen (Operate), and it is the current look.                    |
| Body size                    | Hallmark: 16px minimum                                                                                                | 14px (`text-sm`) for data and controls; 16px on mobile inputs                      | Taste's app-screen measurements and the existing UI; 16px inputs stop iOS zoom. |
| Press feedback               | Emil: `scale(0.97)`; Hallmark: 1px drop                                                                               | `active:scale-98` on buttons only                                                  | Subtle, layout-safe, one rule.                                                  |
| Easing                       | Emil allows plain `ease` for colour; Hallmark bans browser `ease`; Hallmark uses ease-in for exits; Emil bans ease-in | Custom ease-out for enters and hovers, ease-in-out for moves, no ease-in           | Fewer curves, consistent feel.                                                  |
| Durations                    | Hallmark long = 420ms; Emil ≤ 300ms; Open Design ≤ 500ms                                                              | 120 / 200 / 250ms, ceiling 300ms                                                   | A tool used all day should feel fast.                                           |
| Violet                       | Taste and Open Design flag violet/indigo accents; the app uses violet for AI                                          | Violet kept, but only on AI features, never as the general accent                  | Existing meaning users already learned; scoped so it is a signal, not a theme.  |
| Animation library            | GSAP skill recommends GSAP for React; Emil recommends `motion`                                                        | CSS first; `motion` for app exit/layout cases; GSAP only for a future landing page | Matches the job each is best at, and keeps the bundle small.                    |
| Table heads                  | DESIGN.md example uses tracked caps labels; Taste, Hallmark, Impeccable ban them                                      | Sentence case, no tracking (existing caps are legacy)                              | Three sources agree, backed by Taste's measurements.                            |
| Em dash                      | Hallmark bans em dashes; Taste uses one for missing values                                                            | Em dash only as the missing-value glyph                                            | Keeps the table convention, removes it from prose.                              |

## What was skipped and why

- **Running any script, CLI or `npx` command** from the repos (Impeccable's context/detector
  binary, Hallmark's `sloplint`, Taste's `draw.mjs`/`inspect.mjs`, UI/UX Pro Max's `search.py`,
  the `@google/design.md` linter): not run, per the instruction to read only. The skill uses
  their rules directly instead.
- **Theme dealing / direction libraries** (Hallmark themes, Taste's directions and app styles,
  UI/UX Pro Max's 192 palettes): built for new pages or redesigns. This app already has a
  visual system; the skill refines it rather than dealing a new one.
- **Marketing-page rules** (hero composition, word budgets, imagery sourcing, landing
  macrostructures): no landing page exists. Only the anti-template rules that also apply to app
  screens were kept.
- **Native mobile, Expo, SwiftUI guidance** (Emil's `write-swift`, `mobile-native`, UI/UX Pro
  Max native rules): web app only.
- **Scroll World pipeline:** needs paid AI image and video generation; wrong product type.
- **Canvas UI and React Bits component code:** not copied (license and fit). Kept as a decision
  rule only.
- **Brand DESIGN.md files** from awesome-design-md: read for structure only; copying another
  brand's identity is out of scope.
